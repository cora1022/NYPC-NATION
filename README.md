# NYPC NATION

NYPC 마스터트랙 예선 문제인 **NEXT NATION**을 분석하며 만든 전략 봇 제출 기록입니다.  
이 저장소에는 제출 코드 스냅샷, 공식 제공 테스트 도구, 그리고 대회 룰과 개선 과정을 다시 따라갈 수 있는 정리 문서를 함께 남겼습니다.

## NEXT NATION 룰 요약

NEXT NATION은 전장 위에서 두 플레이어가 본부와 거점을 중심으로 전사를 운용하는 턴제 전략 게임입니다. 핵심은 금화 생산, 병력 이동, 건물 업그레이드, 방어와 공격 타이밍을 동시에 관리하는 것입니다.

### 전장과 시작 조건

- 전장은 `0`번부터 `N-1`번까지의 구역으로 나뉩니다.
- 양끝 구역에는 각 플레이어의 본부가 있습니다.
- 본부가 없는 일부 구역은 기지를 지을 수 있는 거점입니다.
- 각 플레이어는 본부 레벨 1, 전사 3명, 금화 500개로 시작합니다.
- 본부가 파괴되면 패배합니다.

### 하루의 진행

매일 플레이어는 명령을 제출하고, 하루는 아래 순서로 처리됩니다.

1. 아침
   - 건설 또는 업그레이드
   - 전사 이동
   - 본부 전사 훈련
2. 낮
   - 건물 포탑과 전사 간 전투
3. 저녁
   - 건물 노동으로 금화 생산
   - 전사 식비 소모, 식비 부족 시 체력 감소

### 명령

- `MOVE a d`: 전사 `a`를 `d`번 구역으로 이동시킵니다.
- `TRAIN n`: 본부에서 전사 `n`명을 훈련합니다. 하루에 한 번만 사용할 수 있습니다.
- `UPGRADE d`: `d`번 구역의 아군 건물을 업그레이드하거나 수리합니다. 비어 있는 거점이면 기지를 건설합니다.

명령은 유효해야 하며, 유효하지 않은 명령은 즉시 패배로 이어질 수 있습니다.

### 경제와 건물

- 본부와 기지는 매일 저녁 전사가 노동할 때 금화를 생산합니다.
- 본부는 전사를 훈련할 수 있고, 레벨이 오를수록 전사 체력, 본부 체력, 포탑 공격력, 노동 효율이 증가합니다.
- 기지는 전사를 훈련하지 못하지만 금화 생산과 방어 거점 역할을 합니다.
- 건물은 업그레이드 또는 수리 시 최대 체력까지 회복됩니다.

### 이동과 전투

- 이동 중인 전사는 목적지까지 최단 경로를 따라 하루에 한 구역씩 이동합니다.
- 같은 구역에 적 전사가 있으면 이동하지 못하고 전투가 발생합니다.
- 건물은 전투 단계 시작 시 포탑 공격을 수행합니다.
- 전사는 체력이 가장 낮은 상대 전사를 우선 공격하고, 전사가 없으면 건물을 공격합니다.

### 종료 조건

- 200일 안에 한쪽 본부가 파괴되면 남은 플레이어가 승리합니다.
- 두 본부가 동시에 파괴되거나 200일 동안 양쪽 본부가 남아 있으면 본부 체력이 높은 쪽이 승리합니다.
- 본부 체력도 같으면 무승부입니다.

## 인터랙션 흐름

프로그램은 표준 입력과 표준 출력을 통해 심판과 통신합니다.

```text
READY LEFT|RIGHT
...
OK

START TURN T
COMMAND
MOVE ...
TRAIN ...
UPGRADE ...
END

TURN T
TIME ...
UPGRADE ...
TRAIN ...
MOVE ...
DAMAGE ...
SIEGE ...
END

FINISH
```

초기 `READY` 단계에서는 맵과 진영 정보를 받고 `OK`를 출력해야 합니다. 매 턴 `START TURN T`를 받으면 제한 시간 안에 `COMMAND`부터 `END`까지 명령 목록을 출력합니다. 게임이 끝나면 `FINISH`를 받고 즉시 종료해야 합니다.

## 진행 과정

### 6월 29일: 룰 분석과 첫 전략 분화

초기에는 거점 수, 금화 생산량, 중앙 거점 가치, 본부 업그레이드 타이밍을 중심으로 룰을 분석했습니다. 이후 경제형, 성장형, 러시형처럼 서로 다른 방향의 봇을 나누어 실험했습니다.

### 6월 30일 ~ 7월 1일: 로그 기반 개선

첫 목표는 넥슨 봇 상대 안정적인 승리였습니다. 제출 로그를 보며 상대 병력의 도착 턴, 거점 방어 병력, 건물 레벨을 기준으로 공격과 수비 판단을 조정했습니다. 단순히 LLM에 구현을 맡기는 방식은 WA와 의도하지 않은 행동을 만들었고, 이후부터는 룰과 로그를 직접 해석하며 수정 범위를 좁혔습니다.

### 7월 2일 ~ 7월 3일: 공격 전략과 구조화

상위권 로그를 참고해 중앙 집결, 외곽 거점 타격, 본진 압박 전략을 실험했습니다. 조건문을 계속 덧대는 방식의 한계를 느끼고, 관측 시스템, 경제 시스템, 공격 시스템, 방어 시스템을 분리하는 컨트롤러 구조로 바꾸기 시작했습니다.

### 7월 4일 ~ 7월 5일: 내부 테스트의 한계

내부 테스트에서는 좋아 보였지만 실제 중간 평가에서는 성능이 떨어지는 상황을 겪었습니다. 특정 내부 봇에게만 강한 방향으로 과적합되는 문제가 있었고, 이후에는 실제 평가 로그에서 반복적으로 드러나는 패턴을 더 중요하게 보았습니다.

### 7월 6일 ~ 7월 8일: 경로 예측과 최종 제출

상대 병력의 최종 도착지를 예측하기 위해 다익스트라 기반 경로 분석을 도입했습니다. 마지막에는 경제형 봇을 중심으로 방어 우선순위와 본부 업그레이드 로직을 조정해 최종 제출을 마무리했습니다.
